DiGiTerra: Tabular Machine Learning in the Browser with scikit-learn

A walkthrough of DiGiTerra 0.1.0 on the guided and classic pages, from installation to predictions on new rows, with the verification record

Paige E. DiGirolamo, Rowan R. Terra, Djuna M. Gulliver, and Nancy J. Trun, 2026-09-25

DiGiTerra is a Flask application for data exploration, preprocessing, model training, and inference on tabular data in CSV, Excel, and Parquet files. A file is uploaded in the browser, a scikit-learn estimator (Pedregosa et al., 2011) is fitted through one training route, and every run writes a record that names the SHA-256 of the uploaded file, seed, request, fitted parameters, metrics, data-check findings, and installed package versions. The application runs in a browser against a local or hosted server, or in a desktop window on macOS, Windows, and Linux. This tab follows one example from installation to predictions on new rows with the Palmer penguin file in examples/. The second tab records what the numbers were checked against, and the third tab lists the works cited.

Installation

DiGiTerra 0.1.0 runs on Python 3.11 and 3.12. From the project root, the directory with app.py and requirements.txt, the pinned runtime dependencies install with pip, and either entry point starts the application.

SHELL
pip install -r requirements.txt
python app.py            # web app at http://127.0.0.1:5000, guided page at /guided
python desktop_app.py    # the same application in a desktop window

The desktop window needs pywebview, which is pinned in requirements.txt. The test suite installs from requirements-dev.txt and runs with MPLBACKEND=Agg pytest tests/ -q or make test. make check runs lint, tests, the JavaScript bundle check, and the requirements check.

The prebuilt application for each platform contains the Python interpreter and every dependency, so an end user installs neither Python nor pip. Each build is downloaded from the Releases page of the repository.

  1. macOS: drag DiGiTerra.app into /Applications and double-click the app.
  2. Windows: extract the DiGiTerra folder, for example to C:\Program Files\DiGiTerra, and double-click DiGiTerra.exe.
  3. Linux: extract the DiGiTerra folder, run chmod +x DiGiTerra/DiGiTerra, and start ./DiGiTerra/DiGiTerra.

The desktop launcher picks a random open port, and DIGITERRA_PORT sets a fixed one. With DIGITERRA_DEBUG=1 the launcher writes a log to ~/Library/Logs/DiGiTerra/digiterra.log on macOS, %APPDATA%\DiGiTerra\Logs\digiterra.log on Windows, and ~/.cache/DiGiTerra/logs/digiterra.log on Linux.

A first model

examples/penguins.csv holds the Palmer Archipelago penguin measurements of Gorman et al. (2014): 344 rows, a text target species (Adelie 152, Gentoo 124, Chinstrap 68), two text columns, four numeric columns, and 11 rows with at least one blank. The steps below were carried out on the guided page on 2026-09-25, and the output blocks are the text the page showed.

  1. Start python app.py and open http://127.0.0.1:5000/guided.
  2. In step 1, choose examples/penguins.csv and press Upload. Step 2 opens.
  3. In step 2, choose species as the target. The page proposes the last column of the file, which for this file is sex.
  4. In step 3, keep the proposed task and model and press Fit the model. Step 4 opens when the run ends.

The proposed model is a random forest (RF_classifier, scikit-learn RandomForestClassifier with 100 trees and random_state 42). The 11 rows with a blank were removed under the default blank rule, and the remaining 333 rows were split at random into 266 training rows and 67 test rows. The metrics are computed on the 67 test rows. The baseline predicts the most common training class for every test row, so a model that does not beat 0.4627 on this file has learned nothing that the class counts do not already show.

The list under model.features in manifest.json names the columns the estimator read. On the classic page the transformer step on Model Preprocessing sets the encoded columns.

The guided and classic pages

The guided page at /guided is four steps in one column: upload a table, choose the target, choose the model and run, and read the result. One step is on screen at a time and fills the window, so the page does not scroll. The step buttons in the header and the Back and Next buttons move between steps that are already open. A step opens when the previous step has produced the input the next step needs, and the upload opens steps 2 and 3 together because the target and the model are filled with proposals.

A two-state control at the top selects Guided or Full, and the browser remembers the choice. Guided fills every setting with a default and shows the four steps. Full opens every setting the training route accepts in the same steps: the predictor columns in step 2, and in step 3 the split method (random, time-ordered, or grouped holdout) and split column, test fraction, stratification column, scaler, blank and zero handling, random seed, decimal places, feature selection with k, outlier method, cross-validation and folds, hyperparameter search, and the hyperparameter table of the chosen model. The words of every control's label are drawn with a dotted underline. Hovering the words opens an explanation, keyboard focus of the control opens the same explanation, and Escape closes it. The explanation is tied to the control with aria-describedby.

The classic page at / is the original interface, with the green masthead, a Documentation view, and a Tutorial. Try an Example loads penguins.csv from the server and opens Data Exploration without an upload. The classic page runs the same training route through six stages.

  1. Upload a CSV, Excel (.xlsx and .xlsm, first sheet only), or Parquet file. The first row of a CSV or Excel file is the header, and the Parquet schema names the columns.
  2. Data Exploration computes correlation matrices, pairplots, and descriptive statistics.
  3. Model Preprocessing selects the indicators and targets, cleaning, and transformations.
  4. Modeling trains the model and computes the metrics.
  5. Inference applies the trained model to a new file. The Inference Results page shows the inference summary, the training plot (predicted against actual, and residuals) with the inference points drawn on the scatter panel, and the inference distribution histogram.
  6. Downloads provide PDF figures and spreadsheet summaries.

On Model Preprocessing, columns are selected with spreadsheet-style letters. A range is written A-D, and several selections are separated with commas, as in A-D, F, H. For penguins.csv, B-G as indicators and A as the target exercise one-hot encoding, missing-value handling, a stratified split, and three-class classification in one run. Indicators are the input columns. Targets are the output columns to predict or cluster. Transformers encode non-numeric columns for modeling, and stratification balances the split or the evaluation on a selected variable. examples/README.md lists the letters for the other nine example files.

Hyperparameters

In Full mode, step 3 shows a table of the chosen estimator's parameters. The route /model-defaults/<name> reads the parameter names from the scikit-learn class and the Default column from the estimator that the trainer builds from an empty form, so the column shows the value that a blank cell leaves. Every trainer falls back to the scikit-learn default for a blank parameter, and the one exception is random_state, which takes the run seed and is shown as "run seed". The classic page's Advanced form sets many of the same parameters under its own field names.

The KNeighbors run in the figure shows the pass-through. The value 3 typed for n_neighbors is recorded as {"n_neighbors": 3} under request.estimatorParams, and the fitted estimator's parameters under model.params hold n_neighbors 3. The run scored accuracy 0.806 on the same 67 test rows against the same baseline of 0.4627. The predictors were not scaled for this run, and a distance model on columns in millimeters and grams is dominated by body mass, so the scaler setting in the same step is the first thing to change for this model.

Hyperparameter search replaces hand-typed values with a cross-validated search. Randomized search tries a sample of combinations, and grid search tries every combination. The values the search chose are written to the run record.

Run record and bundle

Every training run writes manifest.json and model_card.html into the session's output directory. The result links the model card and GET /export-bundle, a zip file of the record with the fitted objects. The bundle from the penguin run holds manifest.json, model_card.html, model_card.json, model.skops, and visualizations.pdf. The manifest has the format name digiterra-bundle/2 and these sections.

Loading a bundle rebuilds fitted objects from a file. The artifact is therefore written with skops (skops developers, n.d.), which stores the objects as data with the type of each object named, and the loader refuses any type outside an exact allowlist (python_scripts/reporting/artifact_allowlist.txt, written by scripts/artifact_type_census.py from every registered estimator). Every bundle is also signed under the installation's key. Import refuses a bundle that is unsigned, altered, or signed by another installation, and installations that share DIGITERRA_BUNDLE_KEY can exchange bundles. The in-app import (POST /import-bundle) is on in the desktop build and off in the container unless DIGITERRA_ALLOW_BUNDLE_IMPORT is set.

Two scripts use a bundle without the web app. scripts/rerun_bundle.py checks the data hash, replays the recorded request, and compares each metric with the recorded value. scripts/score_bundle.py scores a new file and writes the same columns as the web app. Both scripts check the signature under the installation's key file, or under DIGITERRA_BUNDLE_KEY when that variable is set.

Inference on new rows

A model returns a prediction for any row whose columns parse, including a row unlike the training data. Step 4 of the guided page and the Inference page of the classic page write predictions.csv with the input columns, the prediction, and columns that say how far each row is from the training rows. examples/penguins_new.csv is a seeded synthetic file of 22 rows drawn from normal distributions fitted to each species (8 Adelie, 6 Chinstrap, 8 Gentoo), and examples/penguins_new_key.csv records the species each row was drawn from.

  probability_Adelie,probability_Chinstrap,probability_Gentoo,max_probability,novelty_score,novel_row,out_of_range_columns

2,Dream,46.7,18.7,197,3975,Female,Chinstrap,0.01,0.99,0.0,0.99,-0.5020359318822573,False,

For the random forest of the first model, the predicted species matched the key for 21 of 22 rows. No row was marked novel, and no row had a column outside the training range. The one miss is row 1, drawn as a Gentoo and predicted Adelie with a probability of 0.51 against 0.46 for Gentoo, which is also the least certain prediction in the file.

novelty_score comes from an isolation forest (Liu et al., 2008) fitted on the training rows, on the features the model reads. A higher score means a row more like the training rows. novel_row is true when the score falls below the first percentile of the training rows' own scores. The threshold is recorded when the model is trained and is not recomputed from the new file, because a file of unusual rows would otherwise look ordinary against itself. out_of_range_columns lists the numeric columns whose value for that row falls outside the range seen in training, and is empty when none do.

A regression run also writes lower_90 and upper_90, a 90 percent interval from split conformal prediction (Lei et al., 2018). The half-width is the quantile of the absolute residuals on the validation rows, in the units of the target. The interval covers at least nine new rows in ten on average, provided the new rows are exchangeable with the validation rows. The novelty score is the check on that condition, and the interval of a row marked novel should not be relied on. A classification run writes one probability_ column per class and max_probability. An estimator with no probability output writes neither, and the model card records the omission. The model card also records the detector, the threshold, the training ranges, alpha, and the validation size.

scripts/score_bundle.py writes the same columns. For penguins_new.csv and the bundle of the first model, the output of the script matched the web app's predictions.csv in every column and row.

Running the web app

python app.py starts the Flask development server on 127.0.0.1:5000, and DIGITERRA_HOST and DIGITERRA_PORT override the address. For production, gunicorn runs with one worker.

SHELL
gunicorn --bind 0.0.0.0:5000 --workers 1 --worker-class gthread --threads 8 --timeout 120 app:app

Session state is kept in process memory, so a second worker would answer "No data uploaded" for a session that the first worker created. URL_PREFIX serves the app under a prefix as well as at the root. With URL_PREFIX=digiterra the page is at http://127.0.0.1:5000/digiterra/ and at http://127.0.0.1:5000/, and the Dockerfile sets that prefix. Docker and Helm assets are under deploy/, and deploy/README.md describes the build and the install.

Regression stability across seeds

python_scripts/preprocessing/evaluate_regression_robustness.py repeats the train and test split and the cross-validation over a range of seeds. The split is held fixed within each seed, and the script writes per-seed metrics for every model and feature-set combination together with the median, mean, standard deviation, and 95 percent empirical interval.

SHELL
python python_scripts/preprocessing/evaluate_regression_robustness.py \
  --input /path/to/data.xlsx --sheet Literature --target TREE \
  --features pH,Fe,Mn,Al,SO4 --keep-feature pH --stratify-col pH \
  --seed-start 0 --seed-count 30 --output-dir output --output-stem tree_robustness

The run writes output/tree_robustness_per_seed.csv, with one row per seed, model, and feature set, and output/tree_robustness_summary.csv. Thirty seeds are enough for a screen, and the finalist is then confirmed on an external validation dataset.

Accessibility

The guided page is built to WCAG 2.2 at level AA (World Wide Web Consortium, 2024). The page has landmarks, a visible label on every control, errors announced through an assertive live region and progress through a polite one, a visible focus ring, focus moved to each step's heading when the step opens, table headers with scope, a skip link, and no time limit. No meaning is carried by color alone, so each data-check severity is also written as a word. The page is plain HTML and one script, so the accessibility tree is the document tree. tests/integration/test_browser_guided.py runs axe-core in Chromium under the WCAG A and AA rule sets, walks the page by keyboard, and reads a typed hyperparameter back from the fitted estimator. These checks are automated, and no screen-reader session with an assistive-technology user has been run. docs/ACCESSIBILITY.md states what is checked and what is not claimed.

The classic page uses role="navigation", role="status", and labeled role="region" sections, live regions for updates (polite) and errors (assertive), aria-label on controls without visible text, aria-describedby for help text, aria-required on required fields, and aria-invalid on a field that fails validation. A skip link appears on focus, focus moves to the active tab and to error messages, and the tab order follows the page order.

Differential test E1

E1 is a black-box differential test. The same fixed train and test files go into DiGiTerra and four programs written by other people, and every printed value is compared with a plain scikit-learn 1.9.0 script (scripts/oracle.py) that serves as the arbiter. The arbiter is not assumed correct, and the independent engines in R 4.5.1, Excel 16.03, and Altair AI Studio 2026.0.1 are what give a disagreement weight. The diabetes file (Efron et al., 2004) was split once into 353 training and 89 test rows, and the iris file (Fisher, 1936) into 120 and 30, with the split written to disk so that no program performs a separate split, scaling, imputation, or search.

Five cases were run. D1 and D2 are descriptive statistics of the two files. R1 is ordinary least squares on the diabetes training rows, compared on the intercept, ten coefficients, test RMSE, MAE, and R2, and the 89 test predictions. C1 is k-nearest neighbors on iris with k of 5, compared on the 30 predicted classes. C2 is multinomial logistic regression on iris, compared on the classes and the 90 class probabilities; R and AI Studio fit a differently regularized model and were excluded from C2 by plan, and Excel has no classifier.

In R1 the largest relative difference from the arbiter was 3.6e-11 for DiGiTerra (R2 printed to ten decimals), 5.1e-14 for R, 2.0e-14 for Excel, 2.1e-14 for Orange, and 3.8e-13 for AI Studio. All 91 DiGiTerra cells in C2, the class row and the 90 probabilities, are classed same. The 180 cells classed other are Orange's C2 probabilities over two runs, which differ from the arbiter by up to 7.9e-3 while all 30 predicted classes agree. Orange 3.39.0 bundles scikit-learn 1.5.2 on arm64, and the difference is attributed to platform arithmetic under the solver's loose default tolerance. That attribution is inferred and has not been reproduced under Orange's own Python.

E1 found three defects in the version under test, and each was fixed before the counts above were produced. Regression metrics were rounded to three decimals before the decimal-places setting applied. Descriptive statistics were rounded to four decimals, so the centered diabetes means printed as -0.0. For nineteen classifiers, a hyperparameter typed on the Advanced form did not reach the estimator while the run record still recorded the request, so KNeighbors with n_neighbors 3 was fitted with 5. tests/unit/test_decimal_setting.py and test_knn_classifier_form_values_reach_the_estimator cover the fixes, and the pre-fix outputs are kept in digiterra_outputs_pre_fix_99dea69/.

The DiGiTerra side of E1 was run again on 2026-09-25 at commit a32bfa7, after the change to scikit-learn defaults, with the unchanged scripts/run_digiterra.py and scripts/compare.py (docs/differential_test_E1_rerun_2026-09-25/). The five model cases passed the input checks, and every DiGiTerra value in the new RESULTS.csv equals the recorded value exactly. The reference programs were not run again; their saved outputs do not depend on DiGiTerra.

Estimator sweep and artifact round trip

The registry names 69 entries. scripts/train_every_model.py trains each entry on a matching example file through the function that the training route calls, with the hyperparameters that an empty form submits. The record docs/every_model_sweep_2026-09-25c.json, run at commit a32bfa7 in the Linux container with scikit-learn 1.9.0, shows 69 entries trained: 33 regression, 24 classification, and 12 clustering. Until that commit Polynomial and Perceptron were registered without a train function and every sweep skipped them, so the records of 2026-09-24 and of 2026-09-25 at commits 15fe96c and 0b0ae6e show 67 of 69.

scripts/check_artifact_roundtrip.py writes each fitted estimator with skops 0.14.0 under the type allowlist, reads the artifact back, and compares the predictions for the first eight rows exactly. In docs/artifact_roundtrip_2026-09-25c.json, run at commit a32bfa7, 69 of 69 estimators returned equal predictions. birch could not be written before that commit, because skops refuses the Birch type. The artifact now holds BirchCentroids, the arrays that Birch.predict reads, and a loaded Birch model predicts the same labels but cannot be refitted with partial_fit. Against the record at commit 15fe96c, the record at commit 0b0ae6e showed changed first-eight predictions for six models whose defaults changed: RF, ExtraTrees, MLP, gradient_boosting, bisecting_kmeans, and spectral. Each record stores the dataset hash, seed, artifact hash, and both prediction vectors, and --only <model> reruns one estimator against the stored numbers.

Together the two records bound the claim about the registry. The application trains 69 estimators from an empty form and writes and reloads all 69. The records do not show that every hyperparameter of every estimator has been exercised, and the nineteen-classifier finding of E1 is the reason that claim is not made.

The two scripts were also run on an Apple silicon Mac at commit 77c42de (docs/every_model_sweep_2026-09-25d.json and docs/artifact_roundtrip_2026-09-25d.json, Python 3.13.1): 69 of 69 trained and 69 of 69 round-tripped. Against the Linux record, the first-eight predictions are identical for 44 models and agree within 4e-13 relative for 22. RF, ExtraTrees and Bagging differ by up to 3.6 percent. Their training data, seeds and bootstrap rows are bitwise identical on both machines; the trees first differ at exact ties between splits, which scikit-learn's compiled splitter resolves by the last bits of the arithmetic. The Apple silicon build fuses multiplies and adds: scikit-learn 1.9.0 built on the Mac with -ffp-contract=off gives the Linux trees in all 15 model and depth settings tested. A model read from a bundle predicts the same values on both machines, and each machine repeats its own result. scripts/rerun_bundle.py prints a note when a bundle was trained on another operating system or processor type, and scripts/compare_roundtrip_records.py marks tree models that differ between processor types (docs/tree_platform_difference_2026-09-25). The standard DiGiTerra holds to is conformance to the official scikit-learn on the machine that runs it. A run gives exactly what scikit-learn gives when called directly on that machine with the same versions, data and seed, which tests/unit/test_sklearn_conformance.py checks for the tree models. DiGiTerra installs the unmodified scikit-learn release and does not rebuild it to make two processor types agree.

Adversarial check

scripts/adversarial_check.py replays the probes of the adversarial review of 2026-09-24 and prints one line per probe: a crafted artifact that names builtins.eval, path traversal on the download routes, a foreign session, formula cells in the workbook export, a CSV with markup in the headers through both pages, cleared fields, a model-change race, Escape on a focused tooltip, figures in a 720-pixel window, and the review's pipeline tests. The record docs/adversarial_check_2026-09-25c.json, run at commit 0b0ae6e, shows 10 of 10 probes passing, and the pipeline probe reports 37 tests passed. The script is run before a release and after any change to the routes, the pipeline, or either page. CHANGELOG.md lists the defects that the review found and the fix for each.

Fixes of 2026-09-25

Four defects were found while the examples on the first tab were run, and each was fixed at commit 15fe96c. The guided page sent no text predictors to the transformer, so the pipelines kept numeric predictors only; on penguins.csv the model read four of six predictors. The guided hyperparameter table was editable for 20 of 67 models, and for Linear the typed values did not reach the estimator. scripts/score_bundle.py looked for the signing key in a temporary support directory and refused every bundle unless DIGITERRA_BUNDLE_KEY was set. The same script wrote no novelty or range columns. The test suite had not seen the key fault because the suite sets DIGITERRA_APP_SUPPORT_DIR for every subprocess. tests/unit/test_fixes_2026_09_25.py and two new browser tests in tests/integration/test_browser_guided.py cover the four fixes, and the key test failed against the previous script.

A fifth defect was found after those fixes, at commit bde9531. The Default column of the table showed scikit-learn's defaults, while a blank field leaves the value the trainer sets, and 42 of 67 trainers set at least one value other than scikit-learn's (docs/trainer_defaults_2026-09-25.json). For 21 of the 67 the difference goes beyond the run seed as random_state. The column now reads the estimator that each trainer builds from an empty form. At commit 0b0ae6e every trainer falls back to the scikit-learn default for a blank parameter, with random_state taken from the run seed, so the column shows scikit-learn's defaults (docs/trainer_defaults_2026-09-25b.json, 0 of 67 trainers with another value). The previous values stay available in the table and on the classic Advanced form. The sweep and round-trip records above were run after that change.
