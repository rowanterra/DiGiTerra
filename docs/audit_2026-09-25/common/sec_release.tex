\section{Release 0.1.0}
\label{sec:release}

The sections above describe commit \code{4e49ba9}, the copy hosted on EDX. The JOSS submission is release 0.1.0 (commit \code{8e9f171}, 2026-09-27), which is later on the same branch. This section records what was rerun for the release and what changed; \code{CHANGELOG.md} lists every change under 0.1.0.

\paragraph{Sweep and round trip.} Polynomial and Perceptron now have trainers, and Birch is written to the bundle as a centroid artifact (\code{BirchCentroids}), because skops refuses Birch's fitted tree. Every trainer now falls back to scikit-learn's own default for a parameter the form leaves blank, with \code{random\_state} taken from the run seed; before the change, 21 of 67 trainers set a value other than scikit-learn's beyond \code{random\_state} (\code{docs/trainer\_defaults\_2026-09-25.json} and \code{\_25b.json}). The sweep then trains 69 of 69 registry entries (\code{docs/every\_model\_sweep\_2026-09-25c.json}, Linux x86\_64; \code{\_25d.json}, macOS arm64), and the round trip writes and reloads all 69 with identical predictions on both machines (\code{docs/artifact\_roundtrip\_2026-09-25c.json} and \code{\_25d.json}). The four records were written on 2026-09-25; the commits between them and the release change the run record, the pairplot route and the progress stream, not the trainers.

\paragraph{Differential test, rerun.} The DiGiTerra side of E1 was run again at the release tree (\code{docs/differential\_test\_E1\_rerun\_2026-09-25/}). Every DiGiTerra value in the new \code{RESULTS.csv} equals the value in the recorded one: 530 cells, 0 classed other.

\paragraph{Processor types.} Comparing the two round-trip records (\code{scripts/compare\_roundtrip\_records.py}), 44 estimators give identical first-eight predictions on Linux x86\_64 and macOS arm64, 22 differ by no more than $4\times10^{-13}$ relative, and three tree ensembles differ by up to 3.6 percent (Bagging), 1.8 percent (ExtraTrees) and 0.95 percent (random forest). Their training data, seeds and bootstrap rows are bitwise identical on both machines; the trees first differ at exact ties between candidate splits, which the arm64 build of scikit-learn resolves differently because its compiler fuses multiplies and adds. A build of scikit-learn 1.9.0 with fused multiply-add turned off gives the Linux trees on the Mac in all 15 model and depth settings tested (\code{docs/tree\_platform\_difference\_2026-09-25/}). Each machine repeats its own result, and a model read from a bundle predicts the same values on both. The standard DiGiTerra keeps is conformance to the official scikit-learn release on the machine that runs it, which \code{tests/unit/test\_sklearn\_conformance.py} checks for the tree models; the manifest records the operating system and processor type, and \code{scripts/rerun\_bundle.py} prints a note when either differs from the recorded run.

\paragraph{Other changes.} The guided page sends text predictors to the transformer and every model's hyperparameters by their scikit-learn names; a same-column pairplot no longer fails; the progress stream waits for the run record before it reports a result. Each has a regression test named in the changelog.
